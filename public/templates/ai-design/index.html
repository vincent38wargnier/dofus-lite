Direction artistique commune

Plan de création
Lire le prompt
THEME / CE QUE JE VEUX CREER: [describe the project].
Plan a consistent visual identity for a tactical RPG class, dungeon and equipment collection. Deliver a short art bible with palette (hex colours), light direction, materials, silhouette language, readable motifs, and the difference between hero, companion and boss. Keep the UI's elemental colour cues legible.
Create an asset checklist: each distinct character/creature needs 3 core PNGs and up to 6 animation PNGs; each distinct spell may have one 64x64 icon. The map-layer guide outputs, equipment art, covers and arbitrary PNG FX/audio remain design sources. Original flat battlefields and vector effects have a separate runtime contract in references/original-battlefields.md; use that contract when original playable scenery/effects are required.
For every entry specify owner key, exact filename, size, frame count, input references, prompt, current import support and review status (planned / generated / checked). Do not mark a file generated until it exists. Do not change combat mechanics to match the art. Start by approving a front idle and palette; reuse them for all other views. Reference images and descriptions are not sprites.

Lire le prompt
THEME: [theme and approved visual direction].
SPELLS: [names, mechanics, elements and the chosen visualEffect or native visualSpellId].
For each spell describe a short caster gesture, trajectory/impact and sound cue that reads clearly during rapid consecutive casts. For wholly original PLAYABLE visuals, choose a visualEffect descriptor from references/original-battlefields.md: slash, thrust, arrow, ice-lance, shatter, fireball, fire-wave, shield, embers, raven-step, fang, rally or bell; provide two six-digit hex colours and durationMs 250–1500. These use original vector choreography and synthesized audio, without client effect assets. Use a native visualSpellId only when that is wanted. Both options are cosmetic and do not change mechanics. THEME / VISUAL DIRECTION: [theme, palette, materials, light and approved references].
SPELL: [name, element, action, visual motif; mechanics are already defined separately].
Produce ORIGINAL spell-effect art for a tactical RPG, consistent with the approved reference. Effects contain no character, map, ground tile, UI, text, numbers, labels or watermark. Generate each file separately. True alpha transparency, never a painted checkerboard. PNG RGBA 8-bit, non-interlaced, no APNG, no more than 2 MiB per image and 12 MiB per effect folder.
Each default strip is EXACTLY 2048x256: eight 256x256 frames in ONE horizontal row, left to right, no gutters. 24 fps. No part may clip the frame. Use a stable origin and equal scale across frames. If generating separate frames, preserve 256x256 and assemble them without stretching. Guides are technical references to remove before export.
This is a DESIGN package only: put it in design-sources/spell-fx/<spell-key>/, outside the playable ZIP. Neither game importer accepts effect.json or these PNGs. Keep visualSpellId pointing to an existing effect for the playable version. A generic character cast-front/cast-back strip is a different asset. Do not generate executable SWF/JavaScript or change damage, targeting or duration of a combat buff to match the picture.

Generate ONE complete effect folder, using only the layers this spell needs. Basic families: impact, aura, projectile with optional cast/trail/impact, or beam with optional cast/impact. Do not require six layers for every spell. Deliver effect.json and its declared PNGs; keep references, prompts and guides in a separate work folder.
Use the exact schema below. Times are integer milliseconds; duration 100..2000 ms, normally 1500. Frames may be 1..16, fps 8..60, each frame 256x256, sheet width=frames*256. Scale is in percent. Anchors are pixels from the TOP LEFT of each frame. All fields are required; no unrecognised properties.
Role/attachment: cast/caster; projectile/projectile; trail/path; impact/target; aura/caster or target; beam/path. One instance and one PNG per role. Only projectile and beam may use rotation=path. Cast, impact and trail particles cannot loop. Allow each non-looping sheet enough time: endMs-startMs >= frames/fps*1000. All windows fit durationMs. For travel none, startMs=endMs=arcHeightPercent=0. Line travel has arcHeightPercent=0; arc is screen-up quadratic curvature, height=distance*arcHeightPercent/100. Projectile times exactly match travel. Trail emits one stationary particle every 50 ms during travel; it starts with travel and endMs must be at least travel.endMs+frames/fps*1000 so the last particles can fade. Impact begins at or after arrival. A beam uses no travel, rotation=path, anchor (0,128).
Use the per-part prompts and spell-fx/guides/<role>.svg. Read spell-fx/SPEC.md. Open spell-fx/index.html for local playback and checking direction, distance, anchors and timing. From the extracted retro-class-designer kit run: node scripts/check-spell-fx.cjs design-sources/spell-fx/<spell-key>. Fix errors and deliver the JSON report with the design-source ZIP. This checker proves source-format validity only; runtimeImportable MUST remain false. If you cannot run it, say so.
## Drawing instructions for every part (use only the parts this spell needs)
### Lancement — cast.png
Build-up light/magic attached to the caster, not the caster itself. Anchor (128,128). Eight frames: emerging spark, gathering energy, concentration, anticipation peak, release flash, follow-through, dissipation, faint residual glow. One shot, at least 334 ms; almost transparent final frame but still nonempty. Do not loop.

### Projectile — projectile.png
Draw the moving object centred on anchor (128,128), facing RIGHT along +X. Animate energy/flicker IN PLACE in an eight-frame loop; do not move it across the sheet. The viewer applies rotation and line/arc travel. The silhouette and mass stay stable, and frame 8 joins frame 1. No baked arc, long trail or target explosion.

### Traînée — trail.png
One small dissipating particle/puff at anchor (128,128), not an entire path. Eight frames, from bright coherent particle to faint residual dust, final frame nonempty. It is stamped behind the moving projectile. No camera movement, floor shadow or long baked trajectory.

### Impact — impact.png
One readable impact/explosion, centred at (128,128). Eight successive frames: initial contact, compressed flash, expansion, peak silhouette, fragments, fading energy, residual particles, faint final residue. One shot, at least 334 ms. Final frame remains nonempty. The anchor never moves; intensity expands around it. No screen-wide flash or obscuring the whole battlefield.

### Aura / soin / protection — aura.png
A compact eight-frame seamless loop at anchor (128,128). For a ground ring, use a 2:1 isometric ellipse centred at that anchor; for a vertical glow, declare that in the motif. Keep a clear centre so the actor remains readable. This is a short visual cue, not the duration or hit area of a gameplay buff.

### Rayon — beam.png
A horizontal beam from the LEFT edge midpoint (0,128) towards (256,128), eight-frame energy loop. It is stretched only along X and rotated by the viewer to join caster and target. Keep width/thickness stable, no circles or complex symbols that become distorted. No baked endpoint explosion; use impact.png separately. Unlike other parts, its anchor is (0,128).
