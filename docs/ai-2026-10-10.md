# Audit et amélioration de l’IA de combat

L’IA principale reste un moteur de scores partagé par les personnages, les monstres,
les invocations et les personnages personnalisés. Elle ne contient pas de réseau neuronal
et les nouvelles décisions ne reposent sur aucun identifiant de classe ou de monstre.
Les IA écrites à la main, comme Brutus et Plume, gardent leur propre stratégie ;
`api.suggest()` et `api.maison()` utilisent le cerveau amélioré.

## Données effectivement retrouvées

| Source locale | Contenu exploité | Limite |
| --- | --- | --- |
| Exports de combat | 75 fichiers, 64 journaux distincts lisibles | 10 doublons, 1 fichier illisible |
| Journaux distincts | 910 événements, dont 155 lancers et 10 invocations | Souvent des extraits de tests |
| Règles des exports | Versions 2, 3, 4, 5, 6 et 9 | Pas de reconstruction exacte sous d’anciennes règles |
| Anciens entraînements | Profils CEM par classe et adversaire, résultats et checkpoints | Pas de journal individuel de chaque partie |
| Catalogue actuel | 325 monstres, 643 sorts de monstres distincts | Certains effets restent partiels dans le moteur |

Le jeu n’archivait pas automatiquement toutes les parties. Les fichiers retrouvés
ne permettent donc pas de reconstituer tous les combats depuis le début, ni de mesurer
directement la fréquence du problème signalé avec les invocations. Des situations
contrôlées et de nouveaux combats complets complètent cet historique.

Le relevé détaillé est conservé dans `local-observations/ai-20261010/log-audit.json`.
Le code d’avant modification est figé dans `local-observations/ai-20261010/baseline/src`,
avec un manifeste SHA-256 à côté. Les sauvegardes du navigateur et les journaux sources
n’ont pas été modifiés.

## Changements de décision

| Sujet | Nouvelle prise en compte |
| --- | --- |
| Cible prioritaire | Menace du combattant et de ses invocations ; valeur de leur disparition avec leur maître |
| Invocation adverse | Priorité réduite si son maître est accessible ; exceptions pour un danger réel ou un passage bloqué |
| Invocation alliée | Une unité de blocage cherche le contact ; une invocation sacrificielle accepte un échange utile |
| Zones | Recherche de cases vides permettant de toucher plusieurs cibles, avec pénalité pour les alliés |
| Dégâts | Résistances, armures, zones, renvois, Dérobade, Chance, vols de vie, dégâts cumulés et surdommages |
| PA | Comparaison de combinaisons légales, relances et limites par cible comprises |
| Boosts | Effets immédiats intégrés aux attaques suivantes ; états requis et maîtrise d’arme pris en compte |
| Soutien | Meilleure valorisation des retraits, protections, invisibilité, poisons et effets spéciaux |
| Déplacement | Chemins autour des obstacles, portée minimale, ligne de vue, risque sur la case actuelle et pièges connus |
| Mouvement inutile | L’anticipation pondère le gain apporté par le mouvement, au lieu de récompenser à nouveau tout le sort |
| Information cachée | Pas de lecture des positions invisibles ; évite de répéter une action refusée sur une vue inchangée |

Les ordres réels passent toujours par la validation du moteur. Chaque action déclenche
une nouvelle décision : les résultats aléatoires, morts, déplacements et ressources
réelles remplacent immédiatement les prévisions.

## Recherche et calibration

La recherche compare les budgets de PA avec un petit calcul de combinaisons bornées.
Elle évalue les cibles de zone avant de retenir une visée légale par sort. Pour le
déplacement, elle examine les cases accessibles, puis approfondit les six meilleures
et les trois suites les plus prometteuses. Le calcul reste déterministe : les limites
portent sur le nombre de candidats, sans chronomètre ni tirage du moteur pour choisir
une branche.

Les anciens profils ont été appris avant plusieurs changements de règles. Trois
niveaux de confiance dans ces profils — 100 %, 50 % et 0 % — ont été comparés sur
**864 duels de calibration**, avec les mêmes configurations et les deux côtés.
Le critère combine 80 % de résultat global et 20 % de résultat de la classe la plus
faible. Le réglage partagé **50 %** a été retenu et généré dans
`src/bots/policyCalibration.json`. Les profils historiques n’ont pas été écrasés.

Les graines de calibration commencent à `731000`. Les vérifications finales emploient
d’autres graines. Les corrections finales des rôles des invocations et du coût des
mouvements sont ensuite vérifiées sur ces combats distincts.

L’évaluation fait jouer chaque version avec **ses propres invocations**. Pour les
donjons, on change séparément l’IA du joueur ou celle des monstres, face à un adversaire
figé. Les douze classes utilisent le même équipement de référence au niveau 200,
issu d’un ancien export ; ce test ne prétend pas comparer tous les stuffs possibles.

Les salles comparées sont celles du Bouftou Royal, de l’Abraknyde Ancestral, du Maître
Corbac, du Bworker, du Minotot et de la Gelée Royale Menthe. Une victoire aux points
après la limite de tours n’est **pas** comptée comme un donjon terminé.

## Résultats de la version finale

**576 combats complets**, indépendants de la calibration, ont été joués avec la
graine de campagne `2519087` : 288 duels et deux comparaisons de donjon à 144 combats.
Chaque comparaison de donjon contient 72 configurations rejouées avec les deux IA.

| Comparaison | Ancienne IA | Nouvelle IA |
| --- | --- | --- |
| Victoires dans les duels directs | 82 / 288 | **206 / 288 (71,5 %)** |
| Salles entièrement vaincues par le joueur | 26 / 72 | **32 / 72** |
| Joueurs tués par les monstres | 42 / 72 | **49 / 72** |
| Dégâts des monstres au personnage | 81 375 | **98 202** |
| Dégâts des monstres aux invocations | 45 765 | **19 901** |

Les dégâts portent sur les mêmes 72 configurations de la comparaison des monstres,
en excluant les morts automatiques d’invocations consécutives à celle de leur maître.
Les dégâts au personnage augmentent de **20,7 %**, ceux aux invocations diminuent de
**56,5 %**. Les matchs arrêtés à la limite de tours restent distincts des victoires :
3 avec la nouvelle IA et 4 avec l’ancienne dans chacune des comparaisons de donjon.

Ces gains sont globaux. Dans les 24 duels propres à chaque classe, les victoires vont
de 9 pour le Sadida à 21 pour plusieurs autres classes ; cette version ne domine donc
pas l’ancienne dans tous les matchups.

| Calcul d’une décision de la nouvelle IA | Moyenne mesurée |
| --- | --- |
| Joueurs et invocations, duels | 4,9 ms |
| Joueur équipé contre une salle complète | 17,4 ms |
| Monstres et leurs invocations | 2,1 ms |

Ces temps comprennent la vue et l’API, en exécution CPU concurrente. Le maximum observé
est de 218 ms ; ils dépendent de la machine et de la charge. Le contrôle séparé du
catalogue parcourt **975 situations, 3 281 décisions et 420 sorts effectivement lancés**,
sans erreur ni ordre illégal, sur les **325 monstres**.

La campagne finale ne relève aucune exception et aucun ordre illégal sur information
connue. Elle contient 11 refus de la nouvelle IA face à des adversaires invisibles :
la position réelle peut bloquer une case ou une ligne de vue sans être accessible au bot.
Le bot évite de répéter exactement la même tentative sur une vue inchangée.

Les trois rapports `validated-{duel,dungeon,monsters}-2519087.json` partagent l’empreinte
de politique `d2b12174029bc8c40826f0fb5432829f0235813e0660e4aaf3e05308e7bc3765`.
Les essais précédents, dont ceux marqués `dev`, `final`, `holdout` ou `release`, sont
des étapes de travail ; le tableau ci-dessus utilise uniquement les rapports `validated`.

## Vérifications

La suite complète passe : **1 111 tests dans 47 fichiers**, dont 22 tests dédiés aux
décisions tactiques. La compilation de production réussit et la version servie a été
reconstruite après les dernières corrections.

Les tests de décisions passent par les vrais sorts personnalisés et la validation du
moteur : priorité au maître, menace, zones vides, combinaisons de PA, boost immédiat,
renvois, Dérobade, détour, refus d’action, dégâts alliés, invocations et mouvements inutiles.
Le contrôle du catalogue joue trois situations par monstre, puis plusieurs actions
réelles ; il vérifie la légalité et l’absence d’erreur, sans prétendre prouver une
stratégie optimale pour chacun des 643 sorts.

Les résultats complets, actions invalides et durées sont enregistrés en JSON/JSONL
dans `local-observations/ai-20261010`. Les refus dus à une position invisible sont
identifiés séparément des erreurs sur information connue.

Dans Chrome, le personnage équipé termine réellement la salle du Bouftou Royal :
**8 monstres vaincus en 2 tours, 2 203 / 2 509 PV restants**, sans erreur JavaScript
ni action refusée. Le replay, l’export et l’affichage sans débordement sont vérifiés
sur ordinateur et sur trois tailles mobiles.

## Reproduire

```bash
npm run ai:audit-logs
npm run ai:audit-catalogue
AI_SEED=2519087 npm run ai:benchmark -- duel
AI_SEED=2519087 npm run ai:benchmark -- dungeon
AI_SEED=2519087 npm run ai:benchmark -- monsters

# Recalibration ; nécessite le snapshot adverse de référence.
AI_SEED=731000 npm run ai:benchmark -- calibrate
npm run ai:calibrate -- local-observations/ai-20261010/calibrate-731000.json

CI=true npm test -- --watchAll=false --runInBand
npm run build
npm run proof:auto-dungeon
```

`AI_BASELINE` peut désigner un autre snapshot contenant `engine/` et `bots/`.
`AI_WORKERS` règle le parallélisme CPU ; `AI_OUTPUT` change le préfixe de sortie.
Les fichiers locaux de résultats et les snapshots sont ignorés par Git.

## Limites

L’IA estime un court enchaînement et le danger adverse ; elle ne résout pas tout
le combat sur plusieurs tours. Les jets, les déplacements adverses, les synergies
longues et certaines capacités de boss restent approximatifs. Les gains varient
selon la classe, le stuff et la carte. Les effets absents du simulateur ne peuvent
pas être récupérés par l’IA seule.

Le CPU local a suffi. La machine distante proposée a seulement été vérifiée en
lecture ; aucun entraînement, transfert de données ou installation n’y a été effectué.
